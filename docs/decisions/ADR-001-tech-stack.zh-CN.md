# ADR-001 — 本地 Python 应用及受约束技术栈

日期：2026-09-15  
状态：技术栈由用户指定；应用组织方式为待审阅建议，不构成实施批准。  
英文对应文档：[ADR-001-tech-stack.md](ADR-001-tech-stack.md)

## 背景

作品集 MVP 必须以简易配置支持表格接收、确定性分析、五个应用区域及 Excel/PDF 报告。最新架构任务明确指定技术栈。PRD 此前“技术待定”的措辞已成为历史，其开放业务决策仍开放。

## 决策

采用单一本地 Python 应用和同步服务函数，按 [ARCHITECTURE](../../ARCHITECTURE.zh-CN.md) 划分边界。下列职责使用指定工具：

| 技术 | 职责 |
| --- | --- |
| Python | 应用服务、确定性规则、标准记录、配置、日志及标准测试设施 |
| Streamlit | 本地 UI、导航、输入控件、当前交互状态及下载 |
| Pandas | 表格解析/转换，以及依据批准定义的领域分析 |
| Plotly | 交互展示已计算分析序列 |
| SQLite | 本地持久化规范数据及来源，见 ADR-002 |
| OpenPyXL | Excel 解码支持及基于值的 Excel 报告渲染 |
| ReportLab | PDF 布局、表格及基于已计算序列的简单静态图 |

Streamlit 页面调用服务，不实现 KPI。纯领域函数不导入 UI 或 I/O 适配器。渲染器消费结果，不消费原始数据或仓库。实施准备时确定兼容的包/运行时版本；本决策不猜测锁定版本、不创建依赖文件。

PDF 图表使用 ReportLab 根据准备好的序列绘制，不转换 Plotly 输出。其文档布局和图形能力见 [ReportLab 用户指南](https://www.reportlab.com/docs/reportlab-userguide.pdf)。不引入 Kaleido/浏览器图像导出依赖。Streamlit 保存临时交互状态；持久记录属于 SQLite，符合其 [会话状态模型](https://docs.streamlit.io/develop/concepts/architecture/session-state)。

## 考虑的替代方案

| 替代方案 | 处理 |
| --- | --- |
| 独立 API 加 JavaScript 前端 | 拒绝：没有必需的独立客户端，却增加部署和契约。 |
| 所有逻辑放 Streamlit 页面 | 拒绝：重复规则，阻碍独立分析/报告测试。 |
| 仅 Notebook 演示 | 拒绝：不提供必需应用流程和区域。 |
| 为 PDF 建 Plotly 图片导出流程 | 不选：增加渲染依赖；建议版式下简单 ReportLab 图表足够。 |
| 通用插件系统或依赖注入容器 | 拒绝：普通函数和具体仓库足够。 |

## 影响与限制

单进程、单语言减少运行配置。简单服务边界保留可测试性，不引入企业模式。交互/静态渲染器需用同一数据进行视觉验证，但不重复指标计算。

长操作占用本地工作流程；不暗示异步服务或未经测量的性能承诺。若批准负载测量显示问题，先优化相关函数，再提出新基础设施。更丰富的报告视觉要求应经审阅，不能静默增加渲染栈。

本 ADR 不冻结结构、公式、异常阈值、页面版式、报告语言或可选 AI 发布范围。这些仍归专门文档及 PRD 决策登记。

## 验证与重新审阅条件

实施验收前展示离线 F01–F12 流程，核对导入依赖，确认页面/渲染器无业务计算，并视觉检查 PDF 样例。本次文档任务未安装包、运行基准或执行应用。

仅在批准需求无法由当前栈合理满足时重新审阅。增加重大依赖前解释必要性、简单替代方案和成本。见 [ADR-002](ADR-002-database.zh-CN.md)、[ADR-003](ADR-003-ai-boundary.zh-CN.md)。
