# ADR-002 — 单一具体仓库封装 SQLite

日期：2026-09-15  
状态：SQLite 由用户指定；仓库/事务设计待审阅。D05 业务导入策略仍未解决。  
英文对应文档：[ADR-002-database.md](ADR-002-database.md)

## 背景

F04 要求规范化制造数据在重启后保留，同时校验失败不得替换已接受数据。本地单用户作品集需要持久存储，无需独立数据库服务。SQLite 现为明确要求；用户指令解决了章程此前对引入数据库的谨慎限制，而非智能体凭偏好静默覆盖。

## 决策

通过 Python 标准 `sqlite3` 模块及一个具体仓库使用单个本地 SQLite 数据库。不使用 ORM、通用仓库层次、服务器数据库、共享全局连接或连接池。

仓库负责连接、参数化 SQL、原子写入、一致读取和结构版本检查。服务编排操作；领域函数接收记录，独立于 SQL 执行业务计算。仓库 SQL 不计算制造 KPI 或异常。见 [架构第 5–7 节](../../ARCHITECTURE.zh-CN.md#5-依赖方向与边界契约)。

存储四域规范化数据，以及识别已接受输入所需的来源/版本元数据。具体关系结构及约束遵循未来 `docs/data/DATA_CONTRACT.md`；本文不批准 DDL。派生分析重算，不作为竞争的权威数据集存储。默认不在数据库存档完整源文件、被拒原始批次、报告文件或 AI 草稿。

写事务前校验/规范化。全部受影响域及当前数据集元数据一起提交，失败回滚。在一致快照中读取当前身份和所需记录，计算、渲染或外部调用前关闭连接。实施时明确选择事务行为，不依赖随版本变化的默认设置。SQLite 访问、事务控制和参数绑定见 [Python sqlite3 参考](https://docs.python.org/3/library/sqlite3.html)。

针对 PRD **建议的**整批替换，移除旧当前行和发布新行必须处于同一事务。这说明**若 D05 获批**如何安全替换，不决定替换或合并、重复等价性及历史保留。仅按约定身份策略判定重复导入是否不作变更。

重启后重新打开并核对结构版本。不兼容则拒绝，不破坏性重置。初期少量明确版本化结构变更足够，不选择迁移框架。提交结果不确定时，重试前检查持久化身份。锁冲突采用有限等待和明确恢复指引。

## 考虑的替代方案

| 替代方案 | 处理 |
| --- | --- |
| 仅 Streamlit 会话状态 | 拒绝：不能跨重启持久保存规范化记录。 |
| CSV/Excel 作为当前数据库 | 拒绝：不符合 SQLite 约束，且增加跨域原子变更复杂度。 |
| PostgreSQL 或托管数据库 | 拒绝：没有批准的多用户要求，却增加服务和凭据。 |
| ORM / 通用仓库 | 不选：具体 SQL 模块以更少抽象覆盖小范围。 |
| 持久化全部派生 KPI/报告 | 不选：产生过期派生副本和历史管理范围。 |

## 影响与限制

形成小型持久化边界，便于用临时磁盘数据库测试失败。不承诺多用户吞吐、高可用、自动备份、库存交易历史或企业审计。数据库和生成的演示产物是本地运行数据，不是含秘密的仓库样例。

连接限定于操作，不在用户阅读页面或 AI 请求期间持有事务。性能和内存限制待约定测量。持久身份及定义版本让服务拒绝复用过期视图/摘要，不要求历史浏览器。

## 验证与重新审阅条件

计划关闭/重开、注入写失败、跨域回滚、一致读取、结构版本拒绝及有限锁等待测试。D05/数据契约正式定义语义后再增加重复/替换测试，不因测试方便推导业务键。

明确批准并发/多工厂要求或测量到存储限制时重新审阅，变更须另行论证并获批。本 ADR 未创建数据库文件、结构、迁移或生产代码。
