# Phase 07——数据读取与验证

状态：已完成。依据：`AGENTS.md`、`ARCHITECTURE.md`、`docs/data/DATA_CONTRACT.md`（C01–C08 草案）。本任务明确授权实现读取和验证，不解决无关的产品决策。

## 结果与边界

读取包含四个指定工作表的单个 XLSX，或四个显式分配领域的 UTF-8 CSV。保留物理来源位置，验证精确字段和合同类型，只进行文档允许的规范化，检查 DATA.R01–R07，返回结构化诊断。任一错误都拒绝整个批次；局部有效候选行继续验证，但不能部分发布。不实现 Streamlit、SQLite 写入、KPI、仪表盘或异常规则。

## 步骤

1. 在 `data.readers` 实现严格读取、来源位置、文件/容量限制和显式解析失败。
2. 在 `domain.normalization` 实现无损字段转换和转换证据。
3. 在 `domain.validation` 实现字段、必填、重复、跨领域及数量/时间规则，提供含计数与来源的 `ValidationIssue` 和 `ValidationResult`。
4. 通过简洁的 `services.ingestion` 接口协调读取与验证。
5. 测试两种封装、混合有效/无效行、字段/类型/范围/日期错误、规范化后重复、引用失败、行号和合成样例批次。
6. 运行 `ruff check .` 与 `pytest -q`；通过后记录证据并移至 `completed/`。

## 验收与待决事项

- 四个规范业务模式和别名与数据合同一致；不得依赖 Pandas 隐式 NA/类型推断。
- 错误包含数据集、可定位行和字段、严重度、稳定规则代码、原因及更正建议；文件级错误的行/字段为空。
- 重复错误标识两个来源行；关系错误标识可用的对应行。
- 任一错误使 `accepted=False` 且无已接纳记录；有效候选行仍可供本次检查。解析中止须报告未完成验证，不能报告成功。
- 数据合同仍是草案：本次任务遵循文档明示规则，但不代表产品负责人最终批准。不实现导入激活或指纹/持久化。
