# Manufacturing Operations Intelligence（制造运营智能分析）——项目章程

状态：MVP 初始范围，已完成批判性审查  
日期：2026-09-15  
项目类型：展示制造业数据分析与 Excel/Python 自动化能力的作品集项目

## 1. 问题陈述

制造团队经常使用电子表格记录产量、生产目标、不合格品数量和停机时间。编制管理报告需要反复合并数据、纠错、计算和排版。列定义不一致、重复记录、缺失值以及含糊的 KPI 口径，都可能导致误导性结果，即使最终仪表板看起来很可信。

本项目将展示一套可重复执行的流程，将符合约定格式的制造业电子表格转化为经过校验的运营 KPI、交互式仪表板、自动生成的报告，以及 AI 辅助管理摘要。系统将明确展示数据局限，并支持将报告中的数值追溯到源记录。

本产品是小型作品集 MVP，并非用于商业生产的制造执行系统（MES）。项目的可信度来自完整、易于理解的流程以及正确性证据，而不是功能数量。

## 2. 目标用户

| 用户 | 主要需求 |
| --- | --- |
| 生产主管 | 按日期、产线和班次查看产量、不合格品数量及停机情况。 |
| 运营经理 | 识别表现不佳的时段和产线，获得简明的管理报告。 |
| 运营或制造业分析师 | 用可复现流程替代周期性的表格合并和 KPI 编制工作。 |
| Upwork 客户或潜在雇主 | 通过可运行的案例评估 Excel/Python 自动化、数据校验、分析及工程能力。 |

演示假设由一名分析师操作应用，分析一个虚构制造工厂的数据。本 MVP 不需要多用户账号或团队并发协作流程。

## 3. 业务价值

- 通过从导入到报告的一体化流程，减少重复的人工准备工作。
- 在数据错误演变为管理结论之前将其暴露出来。
- 保持仪表板、导出文件和文字摘要中的 KPI 定义一致。
- 帮助管理者定位值得进一步调查的时段和产线。
- 展示一种可复用方法，便于客户将其适配到特定的电子表格报告流程。

节省的时间将通过有记录的示例工作流程进行测量。没有证据时，不宣称工厂生产效率提升、财务回报或真实客户成效。

## 4. 项目目标

1. 交付一条完整流程：导入电子表格 → 校验 → 计算 → 探索分析 → 导出 → 生成摘要。
2. 建立有文档说明的输入数据规范，以及透明的数据接受和拒绝规则。
3. 实现一组精简的 KPI，使用独立计算进行核对，并明确汇总规则。
4. 基于同一份经过校验的数据集，生成一致的仪表板和报告结果。
5. 展示基于计算事实的 AI 辅助写作，并提供可用的离线回退方案。
6. 完成项目包装，使潜在客户能在五分钟内理解其价值，并在本地复现演示。

## 5. 可衡量的成功标准

以下为验收目标，并非已实现的成果。最终作品集必须记录实测结果及未达成的目标。

| 领域 | 验收证据 |
| --- | --- |
| 端到端完整性 | 使用提供的有效工作簿，无需人工修改源数据或中间结果，即可生成仪表板、Excel KPI 导出文件、HTML 管理报告和摘要。 |
| 数据校验 | 每条已记录校验规则对应的预设错误样例均能被检出。阻断性错误会阻止 KPI 和报告生成，并在适用时指出受影响的工作表、行、字段及原因。有效测试样例能够通过校验。 |
| 计算正确性 | 全部五项 KPI 均与独立计算的测试样例一致，涵盖汇总、分母为零和筛选结果为空的情况。数量完全一致；展示的百分比误差不超过 0.01 个百分点。 |
| 输出一致性 | 对同一数据集和筛选条件，仪表板、Excel 导出、HTML 报告及摘要中的事实相互一致。输出注明数据源标识、报告周期、筛选条件和校验状态。 |
| 性能 | 在配置有记录的参考笔记本电脑上，30 秒内处理包含 10,000 行的合成工作簿并生成非 AI 输出，共测量三次。外部模型延迟单独报告。 |
| 重复执行一致性 | 相同输入和设置重复执行后，校验结果及 KPI 一致；允许运行时间戳和 AI 措辞不同。 |
| 自动化价值 | 在同一样本上，记录一套固定的人工电子表格报告流程及其自动化等效流程的准备时间。目标是人工操作准备时间至少减少 50%；报告实际比较结果及其局限。 |
| AI 事实依据与容错 | 在至少五个固定场景中，每项数值陈述均与提供的 KPI 事实一致，不可用值保持不可用，不将缺乏依据的因果解释表述为事实。缺少凭据、超时或 API 失败时，生成有明确标识的确定性摘要，并保留核心输出。 |
| 可复现性与展示 | 按 README 在全新本地环境中完成配置后，能够运行离线演示。三至五分钟的演示同时展示成功流程和无效输入案例。 |

## 6. 范围内功能

### 明确的电子表格输入

- 一个有文档说明的 `.xlsx` 模板，包含一张生产数据工作表；每次运行处理一个工作簿。
- 每行对应一个日期、产线和班次，这三个字段组成唯一键。
- 必需的运营字段：计划产量、实际总产量、不合格品数量、计划生产分钟数和非计划停机分钟数。
- 一个虚构工厂，各产线的数量单位定义具有可比性；合成数据覆盖约 90 天、三条产线和两个班次。
- 提供干净的示例工作簿和刻意包含无效数据的示例工作簿，以及说明单位和假设的数据字典。

### 校验与规范化

- 检查必需列、支持的日期和标识符、数值类型、缺失值、重复键及非负值要求。
- 数量必须为整数；不合格品数量不得超过实际产量；非计划停机时间不得超过计划生产时间。
- 只规范化文档中明确列出的无害格式差异，例如首尾空白字符。记录规范化操作；不得静默填补、删除或修复运营数值。
- 拒绝存在阻断性错误的工作簿，并给出可据此修正问题的校验结果。不得删除无效行后发布基于部分数据的 KPI。
- 对分母为零及筛选结果为空的情况，在适用时明确标记为不可用，避免产生误导性的零百分比。

### 五项运营 KPI

| KPI | 所选记录的计算定义 |
| --- | --- |
| 总产量 | 实际总产量之和。 |
| 合格品产量 | 实际产量之和减去不合格品数量之和。 |
| 生产达成率 | 实际总产量 ÷ 计划产量 × 100。 |
| 不合格品率 | 不合格品数量 ÷ 实际总产量 × 100。 |
| 非计划停机率 | 非计划停机分钟数 ÷ 计划生产分钟数 × 100。 |

比率使用分别汇总后的分子和分母计算，不对各行百分比取平均。生产达成率可以超过 100%。分母为零时结果为不可用。计划生产分钟数不包含计划休息时间；非计划停机时间属于计划生产时间的一部分。这些口径需作为演示定义明确记录，不宣称其适用于所有工厂。

### 一个仪表板

- 一个本地仪表板，支持按日期、产线和班次筛选。
- 展示 KPI 卡片、每日趋势和产线对比视图。
- 明确展示校验状态、数据覆盖范围、指标定义和数据不可用状态。
- 不提供可配置的仪表板构建器，也不为不同用户角色分别开发页面。

### 自动化报告

- 用户触发一次运行，生成包含 KPI 表格和校验结果的 Excel 工作簿，以及包含固定图表和摘要的自包含 HTML 管理报告。
- 报告与仪表板使用相同的所选记录及计算结果。
- 包含足以复现和调查结果的运行元数据及数据源引用。
- 自动化是指无需人工组装报告即可重复执行；定时调度和报告分发不属于 MVP。

### AI 辅助管理摘要

- 集成一个可选用的模型，根据限定范围内的已计算 KPI、对比结果和数据质量说明生成简短草稿。
- 摘要包含观察结果、局限以及建议进一步调查的问题。不得编造原因、缺失值或生产指令。
- 仅向模型提供汇总事实；凭据不进入代码仓库。
- 将文字标记为 AI 辅助生成且需人工复核。使用确定性模板摘要支持离线运行及模型故障时的回退。
- 模型不负责计算 KPI，也不控制任何应用操作或工厂动作。

## 7. 范围外功能

- 生产 MES 功能：工单执行、排程、派工、库存、维护流程和设备控制。
- 与设备、PLC、SCADA、ERP 或外部数据库的实时集成；流式数据和实时告警。
- 任意电子表格解析、多种客户模板、扫描文档及 PDF 导入。
- 多工厂、混合计量单位的产品对比、多租户、身份认证、角色权限及审批流程。
- 设备综合效率（OEE）、预测性维护、预测、异常检测模型、因果分析、优化及财务影响估算。
- 对话式聊天、检索系统、自主智能体、模型训练及多个模型供应商。
- 定时任务、邮件发送、通知、PDF/PowerPoint 导出、移动应用及仪表板定制。
- 微服务、消息队列、分布式处理、生产级高可用、企业审计系统及合规认证。
- 强制云部署，或接收客户数据的公共服务。

## 8. 项目约束

- **规模：** 一名开发者、一个工厂、一套输入数据规范、五项 KPI、一个仪表板和两种导出格式。
- **工时预算：** 目标为 40–60 小时的专注开发时间，包含测试、文档和演示材料。这是初步估算；应先削减额外展示内容，再考虑扩大预算，不应削弱校验。
- **架构：** 优先采用单个 Python 应用，使用少量职责清晰的模块和本地文件。独立后端服务、前端框架或持久化数据库必须有明确的 MVP 需求作为依据。
- **数据：** 使用明确标记的合成数据，并披露假设。不得暗示其代表真实客户或实测工厂绩效。
- **运行：** 核心流程必须能够在本地运行，无需付费服务。运行时可选择是否使用 AI；其成本和延迟必须有边界并形成说明。
- **工程实践：** 提供依赖配置、有实际价值的数据校验和 KPI 测试、清晰的错误信息，以及简短的设计权衡说明。避免为假想的未来客户构建框架或抽象层。
- **变更控制：** 新增功能必须替换工作量相近的现有功能，否则延期。完整演示优先于扩大待办功能列表。

## 9. 主要风险

| 风险 | 影响 | MVP 应对措施 |
| --- | --- | --- |
| 范围向 MES 或通用分析平台扩张 | 项目过大，难以完成和讲清楚。 | 严格执行范围排除项和固定功能数量；新增需求延期。 |
| 输入假设与客户表格不相似 | 作品集精美但缺乏实用性。 | 记录输入规范，展示真实工作中常见的重复记录、缺失值和格式不一致；说明新模板需要适配。 |
| 比率计算错误或计量单位不兼容 | 输出误导用户。 | 明确定义，使用可比较的样本单位、先汇总再求比率的方式，以及独立计算的测试样例。 |
| 静默清洗掩盖运营数据问题 | 报告呈现的可信度高于源数据。 | 记录规范化操作，存在阻断性错误时停止发布。 |
| AI 编造解释或外部服务故障 | 摘要损害信任或阻断演示。 | 仅提供汇总事实，评估固定场景，要求人工复核，并提供离线回退。 |
| 合成数据夸大所展示的业务影响 | 客户预期超出现有证据。 | 标记所有示例，区分实测流程耗时与假设的业务收益。 |
| 环境配置困难或仪表板过度美化耗尽预算 | 核心流程或作品集包装未完成。 | 简化本地配置，尽早展示完整流程，限制图表和布局变体。 |

## 10. 最终作品集交付物

1. **可运行的代码仓库：** 小型 Python 应用，提供可复现的配置步骤，以及针对数据校验、KPI 正确性和端到端流程的有效测试。
2. **示例数据包：** 输入模板、干净的合成数据集、无效示例及简明数据字典。
3. **可用仪表板：** 上述单一仪表板，清楚展示指标和失败状态。
4. **输出示例：** Excel KPI/校验工作簿及 HTML 管理报告，包含明确标记的 AI 辅助摘要和回退摘要示例。
5. **工程文档：** README、本章程、KPI 定义、输入及校验规则、简要架构说明、局限和验收结果。
6. **作品集案例说明：** 解释业务问题、工作流程、工程决策、实测准备时间对比，以及现实可行的客户适配方向。
7. **演示材料：** 三至五分钟的演示，以及少量截图，展示成功流程和可据此修正的数据质量错误。

项目完成要求是集成流程及其支持证据。部署服务、额外分析功能或更多导出格式不是完成前提。

## 11. 范围批判性审查与删减

范围审查围绕一个问题展开：该功能能否在简短的客户演示中，实质性地展示可信的电子表格自动化能力？上述最终范围已纳入以下删减；表中的候选功能不构成交付承诺。

| 应删除或延期的候选功能 | 原因 | 保留的替代方案 |
| --- | --- | --- |
| OEE | 需要可靠的理想节拍及额外的生产时间口径，否则核心指标可能产生误导。 | 五项由输入规范直接支持、定义透明的指标。 |
| 通用 Excel/CSV 导入器 | 任意工作簿映射相当于开发第二个产品，并带来无明确边界的支持负担。 | 一个明确的 Excel 模板。 |
| 停机事件及原因分析 | 增加另一种数据粒度、关联和核对工作。 | 班次级停机总时长和停机率。 |
| 预测及预测分析 | 需要可信历史数据，以及超出作品集目标的评估工作。 | 历史趋势和对比。 |
| PDF 和演示文稿导出 | 重复报告内容，同时增加渲染和排版维护。 | Excel 用于分析，HTML 用于展示。 |
| 调度器、邮件及通知 | 增加运行配置，却没有增强核心演示。 | 用户触发的自动报告生成。 |
| 聊天机器人及自主 AI 操作 | 增加与经过校验的报告无关的交互和可靠性复杂度。 | 一个范围受限、可复核的管理摘要。 |
| 身份认证、云基础设施及数据库 | 解决的是本地演示不存在的多用户服务问题。 | 使用文件、可在本地复现的应用。 |

**剩余范围压力：** AI 集成是最难预测工作量的部分，但项目目的仍支持保留一个有限演示。限定为一个供应商和一种摘要格式。先构建确定性摘要；如果无法完成实时模型集成，应披露这一缺口，不得声称已完成 AI 目标。不要为了优化 AI 展示而移除数据校验或计算检查。

**审查结论：** 立项阶段无需进一步删除核心功能。如果工时估算上升，应优先削减图表变体、视觉定制和可选托管。保留完整的输入到报告流程、有事实依据的摘要行为，以及正确性证据。
