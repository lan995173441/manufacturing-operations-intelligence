# Streamlit UI 评审

日期：2026-09-16。范围：当前作品集 MVP 的五个应用区域。英文对照：[UI_REVIEW.md](UI_REVIEW.md)。

## 依据与限制

已查阅 AGENTS.md、ARCHITECTURE.md、PRD.md、UI 代码和服务结果契约。UI_SPEC.md 尚不存在。V0 历史清单和草案需求不等于设计已定稿；本次变更以现有功能和明确的 UI 评审任务为边界。

证据来自 UI 代码检查与使用合成数据的 Streamlit AppTest，包含全部五个区域及失败状态。本地服务器返回 HTTP 200。系统沙箱拒绝 Chrome 的进程通信端口，导致 Playwright 无法启动浏览器；未完成新的截图或像素级检查。下述密度、换行及布局建议依据代码中的组件顺序和图表尺寸，仍需浏览器验证。本评审属于工程/设计分析，不是用户研究。

现有优点：计算由服务负责、Overview 有六项核心指标、Plotly 配色一致、计划/实际时间趋势和产线对比选型合理、有空状态及库存范围说明。当前最重要的问题是异常检查状态可能造成误判，以及数据激活和校验反馈不够清楚。

优先级：**P0** 可能误导运营判断、意外替换当前数据或掩盖导入正确性；**P1** 显著改善日常理解和操作效率；**P2** 在关键问题解决后改善呈现和预期管理。下表共十项，按价值排序；仅实施三项 P0。

## P0 验收与实现边界

- UX-01：无数据、无效数据、不支持的数据结构、部分覆盖、零次完成检查或跳过检查时，不出现绿色“一切正常”式提示；有效且完整的未触发结果仍显示积极提示。配置错误可以恢复，跳过原因可见，检测不变。
- UX-02：有活动数据但未确认时，两种激活按钮均禁用；确认其中一种不授权另一种。首次加载演示数据无需确认。拒绝的上传保留活动批次标识，下一次尝试需要重新确认。
- UX-03：诊断显示工作表/行/字段及关联记录；规范化分页展示所有 INFO 条目，每页 100 条，并显示原始/规范化值。计数直接来自校验结果。保存失败不声称已激活，也不展示原始持久化诊断。
- 应用代码修改仅限 `ui/app.py`。不修改 KPI、规则、数据结构、服务、SQL、报表实现或依赖。同步提供测试及中英文评审/执行计划。
